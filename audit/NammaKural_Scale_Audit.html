The three things that decide this programme

Ninety findings, but the shape of the work comes down to three.

  1. Nothing is authenticated. Login mints no token — a caller simply asserts their identity in a form field. The entire coordinator router is mounted with no auth dependency, so any caller can assign, close or dismiss any grievance in any ward. Public grievance payloads carry every reporter's name, mobile number and account id.
  2. The data layer cannot reach this scale. One SQLite file on one volume, zero indexes on the issues table, every list query a full table scan, blocking AI calls on the async event loop, and an admin console that downloads the entire table into the browser.
  3. It is built for 16 constituencies, not 100. Boundaries cover Greater Chennai Corporation only and a report outside them is refused with a 422 — so 99 of the 100 target offices cannot receive a single grievance today. The constituency map is hardcoded in three separate languages.
Sequencing. S1 and S2 are not negotiable and not parallelisable with the rest — every other sprint either depends on real identity or would have to be redone once it exists. S3 (PostgreSQL) gates S4, S6 and S8.
